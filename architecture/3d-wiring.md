# 三维模拟接线架构

本文是电拓智训接线工作台的长期架构约定。当前目标不是完整电路仿真，而是先闭环验证：从器件库选择器件，放到接线板和 DIN 导轨上，再把导线准确接到真实端子位置，并由线槽自动整理走线。

## 核心结论

使用单一 React Three Fiber 场景承载接线板、导轨、线槽、器件、端子和导线。所有可接线对象共享同一套三维世界坐标，页面不再使用“图片卡片 + React Flow/SVG 端点”拼接视觉结果。

这意味着：

- 接线板的孔、边框、导轨、线槽和紧固件是三维几何体，不是背景图片。
- 器件按官方安装方式放置：DIN 器件吸附到对应导轨，螺钉安装器件固定到安装板；是否移除端子排盖板必须作为训练显示策略单独记录。俯视相机观察整个板，不允许单个器件脱离板面任意旋转。
- 导线端点严格等于端子螺丝的世界坐标，导线和器件不会因页面缩放、滚动或响应式布局而错位。
- 器件库、场景实例、接线关系和未来的电路分析彼此分离，可独立扩展。

## 分层

### 1. 器件资产 ComponentAsset

资产不是实例。一个资产描述“某型号器件是什么”，存放在 `app/training/component-library/`，包含：

- 稳定的 `assetId`、厂商、型号、类别和位号前缀；
- Web 几何来源（优化后的 GLB 或开发期程序化占位模型）；
- 外形包围尺寸和安装方式；
- 端子 ID、显示名称、局部三维坐标、出线方向和内部等电位组；
- 额定电压、电流、极数等器件属性。

资产 JSON 是器件库与场景之间的稳定契约。替换模型时应校准资产数据，不能在 UI 组件中散落手调坐标。

### 2. 场景实例 DeviceInstance

实例描述“这个型号被放在板上哪里”，只保存资产引用、位号、位置和受限旋转。用户从器件库拖入时创建新实例，并根据资产的 `mounting` 元数据执行对应安装约束：DIN 器件吸附到匹配的导轨，螺钉安装器件贴合安装板并显示实际紧固点。器件移动时导线按端子世界坐标实时跟随；移动、接线和拆线统一进入可撤回/重做历史，并在浏览器本地自动保存。复制、删除和保存项目同样只能修改实例状态，不能复制一份资产定义。

接线板采用柜内模板式布局：左右各一条纵向线槽、五条横向线槽、四层 35 mm DIN 导轨。上、中、保护器件预留层和底部端子层只是推荐起始布局，不按器件类型锁死位置，使用者仍可自行调整。

### 3. 端子与导线 SceneWire

端子的权威位置是资产中的局部三维坐标。运行时按以下关系计算：

`端子世界坐标 = 器件实例变换 × 端子局部坐标`

导线只保存 `from` 和 `to` 两个稳定端子 ID。渲染时重新解析两端坐标，然后用 TubeGeometry 生成具有直径、弯角和接线鼻的三维导线。禁止把屏幕像素、百分比或 SVG 路径当成电气连接数据。

### 4. 自动布线

当前路由器采用俯视平面上的线槽路径网络。端子出线先沿 `exitDirection` 短距离离开器件，再投影到最近的横向或纵向线槽入口；从入槽到出槽之间的全部长距离路径只能位于线槽内部中心通道。路由器在线槽交点组成的网络中计算最短路径，不能以降低权重的方式把线槽仅作为“偏好”，也不能在无路时退化成跨板飞线。平行导线只允许在线槽内部宽度范围内使用确定性偏移。

本项目对“走到线槽里面”的可验收定义：

1. 端子螺丝到器件外沿是端子引出段；
2. 器件外沿到最近线槽是短距离入槽段；
3. 跨器件区、跨安装层的长距离段必须完全落在线槽内部路径网络；
4. 到达目标附近后才允许出槽，随后短距离接入目标端子；
5. 导线在线槽段的高度必须低于线槽侧壁顶面，不能悬浮在线槽上方。

规范基线为现行 `GB/T 5226.1-2019`（机械电气安全）与 `GB/T 7251.1-2023`（低压成套设备和控制设备总则）。其中“就近入槽、长线仅在线槽内、最短线槽路径”是项目依据标准中的机械防护、降低短路风险、可检查维护要求制定的柜内工艺规则；它不是对某一条标准原文的逐字引用。三维路径网络实现参考 EPLAN 对线槽自动生成路由路径、连接点进入路由网络后再进行布线的工程模型。

后续扩展顺序：

1. 加入线槽入口、容量和层级数据；
2. 对同束导线排序并复用主干；
3. 检查最小弯曲半径、线径和拥塞；
4. 允许用户锁定局部路径，再对其余部分重新整理。

路由结果是表现数据，电气连接仍由端子 ID 决定。

## 器件库扩展流程

新器件不要直接写进场景组件。开始前必须先执行 `architecture/component-calibration.md` 的真实性与证据门禁，再按以下流程进入器件库：

1. 将官网原始 STEP/STP、资料页和版本信息保存在 `E:\电气模型库\原始模型\厂商\系列\型号\`；原始文件只读保留。
2. 对照官网图片、官方尺寸图和官方 STEP 六视图确认正背面、上下端、DIN 卡扣方向、导轨轴向和毫米尺寸。不得从包围盒或经验直接推断安装朝向。
3. 在 NX 中检查比例、方向、盖板、可动部件和不必要的小零件；端子排接线版本移除盖板。需要动画的操作机构必须在合并静态网格前识别并保留为独立部件。
4. 导出中间模型并转换成 GLB，统一轴向、原点、物理尺寸，合并静态网格并压缩贴图；不得合并需要动画的原始零件。
5. 优化结果放入 `public/models/<manufacturer>/<model>/`，不要覆盖原始 STEP。
6. 新建 `app/training/component-library/<manufacturer>/<model>.json`，填写来源证据、标定状态、属性、外形、安装方式和全部端子。
7. 在端子标定工具（待建设）中将每个端子锚点贴到螺钉/插孔中心，记录局部坐标和出线方向。
8. 按同一毫米基准与 DIN 35 mm 导轨、线槽、接线板和其他器件进行比例对照。
9. 只有全部证据齐全且 `calibrationStatus` 为正式状态，才能将资产加入 `app/training/scene/catalog.ts`；随后通过资产契约测试，并在浏览器实际完成一次拖入、操作机构开闭和接线。

推荐的原始库目录：

```text
E:\电气模型库\
  原始模型\正泰\TB\TB-1506\
  原始模型\正泰\NXB\NXB-125\
  处理记录\
  缩略图\
```

每个型号建议保留 `source.json`，记录官网链接、下载日期、原文件名、单位、版本、许可/使用备注和转换历史。

占位模型不得伪装成厂家精确模型。正式器件必须通过 `architecture/component-calibration.md` 的来源、尺寸、朝向、安装、操作机构和端子坐标全部门禁，并符合 `architecture/real-panel-baseline.md` 的真实板面规则后，才能标记为可用于训练。

## 状态与未来仿真

Zustand 只维护接线场景状态：器件实例、导线和当前交互。`app/circuit-analysis.ts` 保持纯拓扑安全模块；以后增加上电、评分或故障仿真时，应从场景导线投影成电气网络后交给分析模块，不能把仿真规则塞进三维渲染组件。

## 性能边界

- 全板只保留一个 WebGL Canvas。
- 默认不启用实时阴影贴图；以材质明暗和导线功能性轮廓保证辨识度。
- 重复孔位和紧固件使用 InstancedMesh。
- GLB 使用 Draco/Meshopt/KTX2 等优化时，保留未压缩源文件和转换记录。
- 远距离或大量器件可采用 LOD；端子交互层只在当前视口和可接线状态启用。
- 器件库应按厂商/类别延迟加载，不能一次性下载未来全部模型。

## 验收清单

每次修改至少验证：

1. `npm run typecheck`
2. `node --test tests/*.test.mjs`
3. `npm run build`
4. `npm run build:pages`
5. 浏览器从器件库拖入一个器件，确认吸附到 DIN 导轨。
6. 从一个螺丝端子连接到另一个螺丝端子。
7. 对比导线两端世界坐标和两个端子世界坐标，误差必须为零或仅为浮点精度误差。
8. 确认俯视视角、三维洞洞板、无盖端子排和线槽路由没有退化成图片或 DOM 假端点。

`docs/` 是 `npm run build:pages` 生成的发布目录，会被重建；长期说明必须放在 `architecture/` 等源目录中。
